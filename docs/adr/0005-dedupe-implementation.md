# 去重实现在 `lab/` 里重写，不改用素材目录里的现成脚本

去重的三级收敛（字节一致 → 9×8 dhash → 128×128 灰度 MAE）在 `lab/assets.py` 里重写，复用那三个现成脚本的**判定阈值与位序**，但不调用它们。

这条决定要记，因为 ADR-0002 当时算的账是「去重环节改用素材目录里现成的 Python 脚本，净损失接近零」——现在这个环节变了，得说清楚为什么。

三个脚本（`find_dupes.py` / `dupes_perceptual.py` / `verify_dupes.py`）住在素材目录 `/home/xiao/图片/deepseek大肥鱼表情包/`，不在仓库里。这带来两个问题：

1. **它会随素材一起消失。** 素材是外部资产，挪个位置、换个盘、清一次目录，脚本就跟着没了；而「工作台能不能去重」不该由外部资产的存放位置决定。
2. **阈值是行为规范，不是实现细节。** 汉明距离 ≤4、MAE 三档 6/14 —— 这些数决定了去重结果的松紧，属于需要版本控制的东西。留在仓库外，改动就没有历史。

所以：阈值与位序照抄（`lab/assets.py` 的常量注释写明了来源），实现重写进 `lab/assets.py`。

## 代价

- **重采样算法不同。** 本实现用 Pillow 的 LANCZOS，旧的 `find_dupes.py` 用 Pillow 默认的 BICUBIC、`dupes_perceptual.py` 用 ImageMagick。实测同一张图在两边的 dhash 可能差 0–4 位，而阈值恰好是 ≤4 —— 判定结果大体一致，但**不能逐位对照哈希值**（可以对照判定）。MAE 层面差异可忽略（≤0.2）。
- **第三级口径最初收紧过头。** 旧的 `verify_dupes.py` 是三档（<6 同一张 / 6–14 高度相似 / ≥14 不同图），本实现最初把 ≥6 一律丢弃，等于把「高度相似」也划进「不同图」。已改为把 6–14 那一档单列成「疑似」（`DuplicateGroup(kind="suspect")`）交给人看——这种取舍不该由脚本静默替人做。
- 旧脚本仍留在素材目录里。将来要核对判定，注意上面两条。

## 备选

**就地调用那三个脚本**：省一次重写，且天然与历史清理结果一致（那套脚本 2026-10-09 清出过一次，225→217）。没选，理由见上面两条——代价是把工作台的去重能力绑在外部目录上。
